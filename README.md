## 1. 기획

커플 두 명이 **가고 싶은 곳(지도 핀)** 과 **함께할 일정(캘린더)** 을 같이 채워가는 공유 앱. 한 명이 핀을 찍거나 일정을 적으면 상대 폰에 실시간으로 반영된다.

- **타깃**: 데이트 장소와 일정을 카톡·네이버 지도 저장·메모장에 흩어서 관리하는 20~30대 커플
- **핵심 가치**: 데이트 준비(어디 갈지 + 언제 갈지)를 한 앱에서, 둘이 같이
- **공유 방식**: 모든 데이터는 커플 공간에 소속된다. 따로 공유 버튼 없이 둘 다 같은 지도·캘린더를 본다.
- **캘린더**: 빈 캘린더를 둘이 직접 입력하며 채운다. 외부 캘린더 연동이나 각자 일정 관리는 하지 않는다.
- **차별점**: 지도 핀과 캘린더 일정을 연결한다. "가고 싶다"로 저장한 장소를 일정에 넣고, 다녀오면 "가봤다" 기록으로 남는다.
- **넣지 않는 것**: 채팅(이미 카톡을 씀), 실시간 위치 공유(위치정보법 신고 대상 + 감시 느낌)

### 경쟁 앱 조사

| 앱 | 핵심 | 가져올 점 |
| --- | --- | --- |
| 비트윈 | 커플 메신저 + 앨범·다이어리, D-day 위젯, 공유 캘린더, Face ID 잠금 | D-day 위젯, 앱 잠금, 앨범 |
| 썸원 | 매일 질문에 둘 다 답하기, 커플 캐릭터 성장 | 오늘의 질문, 캐릭터·스트릭 |
| Cupla | 공유 캘린더 + 위시리스트, 링크 저장, 둘 다 하트, AI 플래닝 | 링크로 장소 저장, 둘 다 찜, AI 코스 추천 |
| Lovewick | 질문 카드, 데이트 아이디어, 취향 기록, 추억 타임라인 | 취향 노트, 데이트 아이디어 |
| 위젯 앱 (Locket 등) | 상대 홈 위젯에 사진·낙서 보내기, 기분 공유 | 위젯으로 사진 보내기 |
| TimeTree | 공유 캘린더, 일정 댓글 | 일정 댓글 |

지도 핀 + 캘린더 연결을 중심에 둔 커플 앱은 조사 범위에서 찾지 못했다. 이 조합을 차별점으로 가져간다.

### 결정 로그

| 결정 | 이유 |
| --- | --- |
| 지도·장소는 카카오로 통일 | 네이버 검색 API는 결과 5개, 주변 검색 불가 |
| 지도는 카카오맵 JS + WebView | RN용 카카오맵 라이브러리가 지도 기능을 뺐음. 버벅이면 네이티브로 |
| 장소 상세 = 우리 기록 + 카카오 장소 웹뷰 | 사진·리뷰는 API에 없음. 앱만의 가치는 우리 기록 |
| 작성자 표시·활동 알림·채팅 없음 | 둘이 같은 공간을 쓰는 느낌, 채팅은 카톡으로 충분 |
| 캘린더는 둘이 직접 채움 | 각자 일정·외부 연동은 앱의 목적과 다름 |
| 실시간 = STOMP + 복귀 시 /sync | 백엔드로 직접 구현해 포트폴리오로 설명 가능 |
| 내 위치(GPS)는 v2 | 위치기반서비스사업 신고가 먼저 필요 |

## 4. UI 설계

디자인 시스템 전체는 [docs/DESIGN.md](docs/DESIGN.md), 코드 토큰은 [app/src/theme/tokens.ts](app/src/theme/tokens.ts).

### 디자인 원칙

1. **지도와 달력이 주인공** — 꾸밈보다 정보가 먼저. 장식은 빈 상태·온보딩·기념일에서만.
2. **둘이 같은 공간** — 작성자 표시 없음. 둘이 따로 반응하는 기능에서만 두 사람을 구분.
3. **따뜻하지만 유치하지 않게** — 웜톤 배경과 둥근 모서리, 색은 포인트에만.
4. **색에만 의존하지 않는다** — 카테고리·상태·일정 유형은 아이콘·모양으로도 구분.
5. **한 손으로 쓴다** — 자주 누르는 버튼은 아래쪽 절반, 주요 동작은 시트 하단 고정 버튼.

### 탭 구성 · 첫 실행 흐름

| 탭 | 주요 내용 |
| --- | --- |
| 홈 | 사귄 지 N일, 다가오는 기념일, 이번 주 일정, 최근 저장한 장소 |
| 지도 | 검색바(가게·역·동네), 카테고리 칩, 필터, 목록·지도 전환, 장소 바텀시트, 핀 상세 |
| 캘린더 | 월간 달력, 날짜별 일정, 일정 등록 시 저장한 장소 불러오기 |
| 설정 | 커플 프로필, 사귄 날 수정, 알림, 앱 잠금, 연결 해제, 회원 탈퇴 |

첫 실행: **로그인 → 초대코드 만들기/입력 → 사귄 날 입력 → 홈**. 커플 연결 전에는 연결 화면만 보인다. v2부터 탭이 늘면 "더보기"로 묶는다.

## 7. 로컬 개발 환경

### 필수 설치

| 도구 | 버전 | 용도 |
| --- | --- | --- |
| Node.js | LTS (v24) + npm | Expo 앱 (Expo SDK 58). pnpm은 한글 경로에서 설치 중 크래시가 나서 npm 사용 |
| JDK | 21 LTS | Spring Boot |
| Docker Desktop | 최신 | PostgreSQL, Redis |
| Android Studio | 최신 | 안드로이드 에뮬레이터·개발 빌드 |
| Expo 계정 + EAS CLI | 최신 | 개발 빌드, 스토어 빌드 (맥 없이 iOS 빌드) |

### 앱 실행

```bash
cd app
cp .env.example .env        # 값 채우기
npm install
npm start                   # Expo 개발 서버 (화면 확인은 Expo Go로도 가능)
npm run android             # 카카오 로그인 등 네이티브 모듈은 개발 빌드 필요
```

### 인프라 (DB · Redis)

```bash
cd infra
cp .env.example .env
docker compose up -d postgres redis
```

### 체크

```bash
cd app
npm run lint
npm run typecheck
```

## 8. 브랜치 · 커밋 규칙

- `main`: 항상 배포 가능한 상태
- `develop`: 개발 통합 브랜치. 기능 브랜치는 여기서 따고 PR로 합친다
- 기능 브랜치: `feat/F-10-search`, `fix/realtime-reconnect`처럼 기능ID를 이름에 넣는다
- 흐름: `feat/*` → PR → `develop` → (릴리스 시) PR → `main`

```txt
feat(app): 지도 WebView 브리지로 핀 그리기
feat(api): 커플 초대코드 생성·연결 API 추가
fix(realtime): 재연결 시 변경분 누락 수정
docs(adr): ADR-003 지도 WebView 결정 추가
```

타입: feat, fix, refactor, test, docs, chore · 스코프: app, api, realtime, infra, docs
